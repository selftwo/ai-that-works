# Product Specs with AI

Status: curated from the upstream transcript. Transcript evidence only.

## Purpose, audience, and message

Purpose: Show how to split product, technical, and program decisions before implementation.

Audience: Product and engineering teams that use agents for planning and coding.

Message: Make each design stage a reviewable artifact, explore broadly while leverage is high, then increase verification as the plan approaches code.

## Practical lessons

- Separate user outcomes from architecture and function-level design.
- Define success measures when the product question supports them.
- Generate several mockups before selecting a direction.
- Use Markdown for model context and rendered HTML for human review.
- Require a clear plan-deviation report at pull request time.
- Resolve codebase-specific choices during program design.

## Failures and uncertainty

A combined design discussion can settle the user experience but miss implementation choices. Generic repository instructions also go stale. The live mockups and referenced design documents are not included, so transcript claims about them are not independently verified.

## Purpose, audience, and message

Purpose: Demonstrate how a team researches, reviews, versions, and exports design documents before assigning implementation to coding agents.

Audience: Engineering teams using agents on changes where architecture and review matter.

Message: Make design quality and review state explicit, preserve discussion and versions, and use disposable internal tools to support the workflow.

## Tactical practices

- Do background research before settling a design.
- Move a document from draft to proposed only after the author says it is ready to read.
- Keep comments, versions, and decisions attached to the document.
- Use Slack for notifications instead of rebuilding a notification system.
- Export the document and its history as agent context before implementation.

## Failure modes and limits

- Implementation quality cannot recover a wrong design reliably.
- GitHub and scattered documents make long design discussions hard to review.
- Internal support tools can be rough, but the workflow and exported evidence must remain trustworthy.
